# 開発ラインのセキュリティ残存リスク

fake PoC の Security レビューで見つかり、未対応または一部対応のものを記録する。H-1〜H-2 と M-1〜M-4 の対応は `adr-001-devline-foundation.md` を参照。
「状態」はこのブランチのコードで確かめた内容で、実走と本番の確認ではない。

## Medium

| ID  | リスク                                                                                                                                         | 状態                                                                                                                                                                                                                                                      | 対応する時期 |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| M-5 | 追記のみの制約を DB 所有者が迂回できる。制約は行トリガだけで、TRUNCATE、`DISABLE TRIGGER`、`DROP` を止めない。監査の連鎖は全行消去を検知しない | 未対応。所有者とアプリのロール分離、`BEFORE TRUNCATE` トリガ、連鎖の先頭ハッシュの外部保存が必要                                                                                                                                                          | 本番化の前   |
| M-6 | Preview の `GITHUB_TOKEN` は個人の広い権限の可能性がある。worker は `config` 経由でトークンとセッション秘密をプロセス内に持つ                  | 一部対応。実 runner は専用の `DEVLINE_GITHUB_TOKEN` を使い、コンテナへ GitHub トークンを渡さない。1件実走のトークンは所有者の判断で全 repo に届く範囲で、worker の不具合時の影響範囲は Sandbox に限られない。API 側のトークンと worker の `config` は残る | 本番化の前   |
| M-7 | runner への入力に個人情報が残りうる                                                                                                            | 一部対応。実 runner は `requested_by` と `approver` の行を除く。自由記述の検査は無く、作り物のデータ以外を入れてはいけない                                                                                                                                | 実データの前 |
