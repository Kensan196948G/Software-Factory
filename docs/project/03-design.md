## 3. 画面状態

Normal / Empty / Loading / Validation Error / Communication Error / Success を全画面で定義（設計成果物 §12）。トーストは7秒・「元に戻す」は取り消し可能な遷移のみ。エラーはコード（ERR-xxx）と問い合わせIDを表示し、入力は消さない。

### 6-0. 開発ラインの用語（「CI 成功」「PR 候補の準備完了」「受入の合格」を分ける）

仕様の受入条件の検証（GC-43 など）は人の判断を含むので、システムは「受入の合格」を出さない。開発ラインの画面は次の別々の行で示す。定義は `docs/devline/api-contract.md`。

| 仕様・従来の表現                             | 現在の表示                                                                            | 理由                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 自動検査の行は記録の有無だけ（「記録あり」） | 「CI 成功」「CI 失敗」「CI 未完了」を必須段階だけで出す                               | チップの「実行確認済み」は記録が実物という意味で、成功の意味ではない |
| 受入条件の検証                               | 「受入条件 全件確認 / 未確認あり / 不合格あり」。読めないときは「証跡の欠落（理由）」 | CI 成功でも AC の証跡が無ければ未確認                                |
| `pr_ready`                                   | 「PR候補の準備完了・人の確認待ち（受入の合格ではありません）」                        | 合否と merge の判断は人                                              |
