# 承認者選択UIの是正（未配備）

所有者依頼: 2026-11-03、追加承認者本人が不在のため本人ログイン・別人承認の受入は保留し、固定見本の承認者選択UIを先に修正する。

## WHY / WHAT / HOW

- WHY: サーバは有効な承認者名簿と `approverUserId` を扱えるが、接続コンソールの選択欄が見本3名に固定され、IDを保存しないため本番受入が進められなかった。
- WHAT: 接続モードでは有効な登録済み承認者を利用者IDで選択し、POST/PATCH・下書き・再読込・編集へIDを保持する。同姓同名はメール等を併記して区別する。
- HOW: 認証済みHTMLのbootデータに既存 `listApprovers` の結果を追加し、bridgeとconsoleを対応させる。名前だけの旧データ、名簿なし、不正名簿、名簿外IDは明示再選択を求め、先頭や同名の人へ自動置換しない。サーバの有効承認者ID検証を維持する。
- 現在の操作主体はログイン利用者として表示し、オフライン見本の役割名を実行者と混同しない。認可判断の最終正本はサーバのまま。

## 設計との差分

`docs/design/msf-intake-design.html` の役割/ウィザード/承認の画面構成、注文書・状態・信号・エラー契約は変更しない。`offline-Application` の原本は変更せず、接続モードの承認者項目のみを実名簿/ID対応にする。単体オフラインモードの見本候補は維持する。
