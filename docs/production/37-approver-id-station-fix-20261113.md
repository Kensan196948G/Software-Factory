# ステーション画面の承認者を利用者 ID で選ぶ — 回帰の原因と修正（2026-11-13）

作成: 2026-11-13 JST。対象: ステーション画面（`src/web/public/station.js`）の「新しい依頼」STEP 7。
状態: **修正実装済み・未配備**（マージと本番配備は所有者の判断待ち）。API・DB・認可・監査は変更しない。

## 1. 不具合

`approver_user_id` を持つ依頼を承認待ちから進められるのは、その本人だけである（`src/shared/domain.ts` の遷移判定）。
ところが新しい画面の承認者選択は、利用者 ID ではなく表示名で動いていた。

| 箇所（修正前 `5227b080`）      | 内容                                                                                                                                               |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `station.js` 826 行            | `<select data-bind="approver">` の option は表示名だけ（value も表示名）。同名の承認者は同じ項目として並ぶ。表示名は HTML エスケープなしで埋め込む |
| `station.js` 886〜889 行       | 登録時に `approvers.find(a=>a.displayName===d.approver)` で、最初に一致した人の ID を `approverUserId` に入れる                                    |
| `station.js` 881〜885 行       | 編集の保存は `approverUserId` を更新しない                                                                                                         |
| `station-bridge.js` `toServer` | `approverUserId` が名簿にあれば、その人の表示名で `approver` を上書きして送る                                                                      |

実測 4 で PATCH が出ない理由: 編集で変わるのは `approver`（表示名）だけで、`approverUserId` は元のまま残る。
ブリッジは `approverUserId` の人の表示名で `approver` を上書きするので、送る内容がサーバと同じになり、差分なしと判定される。

## 3. 原因

2026-11-11 に旧コンソール（`console.js` / `bridge.js`）から新しい画面へ移植したとき、PR #76（2026-11-03、
`docs/production/05-approver-ui-correction.md`）で入れた「承認者を利用者 ID で選ぶ」挙動が落ちた。
新しい画面は設計の原型（`docs/design/software-factory-station-devsecops.html`）の表示名の一覧をそのまま使い、
登録時だけ表示名から ID を引く処理を足していた。旧画面の回帰テスト（`tests/browser-legacy/approver.spec.ts`）は
画面の置き換えで退避され、新しい画面に同じ観点のテストが無かった。

## 4. 修正

変更は `station.js` だけ（+53 / −13 行。レビュー反映後の合計）。`station-bridge.js`・サーバ・DB は変更しない。

| 項目                       | 修正後                                                                                                                                                                                                                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 選択欄                     | サーバ接続時は `<select data-bind="approverUserId">`。option の value は利用者 ID、表示は表示名                                                                                                                                                                                          |
| 同名の区別                 | 名簿の中で表示名が完全に一致する候補が 2 人以上いるとき、その候補だけにメール（無ければ部署、それも無ければ ID の先頭 8 桁）を併記する。重複しない候補は表示名だけ。人数は `Map` で数える（`constructor`・`__proto__` など、オブジェクトの継承プロパティと同じ表示名でも数え間違えない） |
| 選択の反映                 | 選ぶと `approverUserId` と `approver`（その人の表示名）を同時に更新する。右端のプレビューにも同じ表示が出る                                                                                                                                                                              |
| 初期値                     | 空選択（「承認者を選択してください」）。名簿の先頭の人へ自動で割り当てない（旧画面と同じ）                                                                                                                                                                                               |
| 登録の検証                 | STEP 7 の検証を利用者 ID 基準にした。未選択・名簿に無い ID・名簿なしでは登録へ進まず、STEP 7 に理由を出す                                                                                                                                                                                |
| 編集                       | 保存済みの `approverUserId` を選択状態に復元する。別の人へ変えると `PATCH` で `approverUserId` と `approver` が送られる                                                                                                                                                                  |
| 名簿に無い ID              | 「現在の承認者: ○○（現在は選択できません）」を選べない現在値として表示し、名簿の誰にも置き換えない。選び直すまで保存しない                                                                                                                                                               |
| 名前だけの旧データ         | 空選択に「現在: ○○／利用者IDが未設定」を表示する。同じ名前の人がいても自動で割り当てない。選び直すまで保存しない                                                                                                                                                                         |
| 名簿を取得できない・不正   | 選択欄を無効にし、理由（`approverState.reason`）を表示して登録を止める。見本の名前（鈴木 一郎 など）へ戻さない                                                                                                                                                                           |
| 接続の処理を読めない       | 起動データがあるのにブリッジを読めなかったときも、見本の承認者へ戻さず登録を止める                                                                                                                                                                                                       |
| エスケープ                 | 候補の表示名・メールはすべて `E()` を通す（オフライン見本の一覧も同じ）                                                                                                                                                                                                                  |
| 表示名から ID を引く処理   | 削除した（`approvers.find(a=>a.displayName===d.approver)`）                                                                                                                                                                                                                              |
| システム設定「承認者」タブ | サーバ接続時は名簿（`approverState.items`）をそのまま表示する。同名はメール併記                                                                                                                                                                                                          |
| オフライン単体             | 変更なし。見本の名前の一覧（`data-bind="approver"`）から選び、初期値は先頭の名前                                                                                                                                                                                                         |

送信の直前には、従来どおりブリッジの `requireSelectedApprover`（ERR-004）が利用者 ID の無い依頼を止める（二重の防止）。

### 許容偏差（設計の原型との差）

- サーバ接続時の STEP 7 は、原型の「表示名の一覧・先頭が初期値」ではなく「利用者 ID の一覧・空選択が初期値」とする。
- システム設定「承認者」タブの「新しい依頼の最初の候補」バッジは、サーバ接続時は出さない（初期値が空選択になり、事実と合わなくなるため）。オフライン単体では従来どおり出す。

### 版付け

配信物の版は commit SHA で付く（`src/api/asset-version.ts`、`COMMIT_SHA`）。仕組みの変更は不要で、`asset-version.ts` と
`tests/unit/asset-version.test.ts` は変更していない。

修正前のまま運用した場合に起きること: 承認者の付け替えが画面からできない。同名の承認者が増えると、選んだ人と別の人が承認者になる。

修正後に利用者が気づく変化: STEP 7 で承認者を必ず自分で選ぶ（選ばないと登録できない）。名前だけの旧い依頼と、
承認者が名簿から外れた依頼は、編集のたびに承認者の選び直しを求められる。

## 7. 既知の制限

- 保存の成否を待たずに成功表示を出す作り（`submit()` が同期の結果を待たない）は、この修正の範囲外である（別の PR で直す）。
  この修正が止めるのは、承認者が未選択・名簿外・名簿なしのときの「送信前」までである。送信後にサーバが拒否する場合
  （例: 画面を開いた後に承認者が無効化された）の画面の動きは、この修正では変えておらず、実測もしていない。
- 名簿は画面を開いたときの内容である。開いた後に追加された承認者は、再読み込みするまで選択肢に出ない。
- 注文書 YAML の `approver` は表示名のままである（同名の区別は画面の表示だけ）。
- 名前だけの旧い依頼を一括で利用者 ID に紐付ける移行は行わない（編集時に選び直す）。
- 画面の目視確認（Cloudflare Access 越し）は行っていない。
