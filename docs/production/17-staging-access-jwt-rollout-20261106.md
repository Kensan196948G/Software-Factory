# Staging の Access JWT 検証の有効化と旧セッション失効の記録（2026-11-06）

作成: 2026-11-06 JST。対象は **Staging（`sf.mirai-dx-platform.com`、API `127.0.0.1:8782`、DB `mirai_sf`）だけ**である。本番は変更していない。

- 本書の値は Lead（AI）の実測を転記したもの。AUD・team domain・JWT・トークン・セッション ID・メールアドレス・接続文字列などの実値は書かない。識別には SHA-256 の先頭 8 桁だけを使う。
- 本書は**技術的な切替の記録**であり、正規の Access ログイン（OTP）の成功確認でも、本番の業務受入でもない（§6）。

## 1. 承認

- 2026-11-06、所有者の回答 **Y**: Staging に JWT 検証の 2 項目（`ACCESS_TEAM_DOMAIN` / `ACCESS_AUD`）を設定し、旧セッションを失効する。
- 同時に示した追加案 Q2 / Q3 は**未回答**。本書の作業には含めていない。

## 2. 事前確認（読取りのみ）

- Cloudflare API の GET で、`sf.mirai-dx-platform.com` の self_hosted アプリが 1 件であることと、組織（team）を確認した。
- 設定する値の識別（SHA-256 の先頭 8 桁）: AUD `6df9c82f`、team domain `14250f36`。
- JWKS（`<team>/cdn-cgi/access/certs`）は 2 鍵。
- 既存のセッションは 21 件で、すべて期限切れ（有効 0 件）。切替後の新規作成も 0 件だった。

**実行した SQL の要約**: 独立検証の計画書（`_work/staging-session-revoke-plan`）に載っている計画 SQL とは異なり、実際に実行した SQL は、同一トランザクションの `DO` ブロックの中で、次の 5 条件の検査と削除を行った。

1. `current_database()` が `mirai_sf` である。
2. 対象（cutoff より前の作成）の件数が 21 件で、上限 100 件以下である。
3. `created_at >= cutoff` のセッションが存在しない（切替後の新規が 0 件）。
4. `expires_at > now()` のセッションが存在しない（有効なセッションが 0 件）。
5. 削除の条件は `created_at < cutoff AND expires_at <= now()` とし、削除した件数が 21 件に一致する。

SQL の要約には秘密やセッション ID を含めていない。また、この SQL は `audit_log` への追記をしていない（下記）。

**監査の空白（隠さない）**: この旧セッションの削除は、運用者が DB を直接操作したもので、アプリの `audit_log` には**自動で記録されない**。audit は削除の前後で 142 件のまま変わっていない。「監査ハッシュ連鎖 142 件 OK」は既存の監査行が改ざんされていないことを示すだけで、削除の監査行があることを意味しない。削除の記録は本書（実行者・時刻の範囲・cutoff・条件・事前 dump のファイル名・件数）だけである。

## 5. 逸脱（削除せず残す）

- 05:10:01 の API 再起動が Staging の healthcheck と重なり、停止中の旧 PID が **503 を 1 件**返した。これにより OnFailure の記録（`alerts.jsonl`）が **1 件**残った。
- 05:13:19 以降、監視は回復している。新しい API の PID では 5xx は 0 件。
- 当該のエラーログと alert は**削除していない**。再起動と healthcheck の衝突は、手順で避ける（`docs/deployment.md` §3-1）。
- 旧セッション 21 件の削除は `audit_log` に記録されていない（§3 の「監査の空白」）。アプリの監査だけを見ると、この削除は追えない。

- 本番の業務受入ではない（本番は Q2=3 により業務受入なしで運用中。ADR §8.2）。

## 7. 切り戻しの注意

- JWT の 2 項目を外して元の設定に戻すと、Staging は**再びヘッダを信頼する状態**（Issue #102 の経路が開く状態）になる。
- 回復できずに元の設定へ戻す場合は、戻した後に**セッションを再度失効**し、ヘッダ信頼に戻したことを所有者へ**申告**する。
