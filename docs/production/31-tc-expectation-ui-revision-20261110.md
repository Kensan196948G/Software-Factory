# TC 期待値の UI 改訂手順（G1・G3・G4）

作成: 2026-11-10 09:35 JST。対象: `prj_mw8amy8n_026d34a4`（PRJ-2026-002）。

品質工作台の TC は **期待値（`expected`）を API・会話ツールから更新できない**（状態変更のみ）。以下は UI で編集するための手順と、変更前後の文言である。

## 1. なぜ改訂してよいか（仕様を下げないことの確認）

要件 `docs/project/01-mvp-scope.md:49,75` が求めているのは「空・読込・入力エラー・通信エラー・成功の各状態を**再現できる**こと」であり、次の導線の位置・入力エラーの項目別表示・403 は要求していない。したがって G1・G3 の改訂は**要件を下げるものではなく、TC の過剰指定を実測に合わせる**ものである。G4 は API 契約（`docs/api.md:68`）が 409 と明記しており、実装が正しい。

## 2. 変更対象と根拠

| # | TC | 実測（根拠） | 改訂の内容 |
|---|---|---|---|
| G1 | TC-UI-STATE-01 手順 1 | 空表示に導線は無く、新規作成は**左レール**にある（`27` §4-2） | 「次の導線（新規作成・再読込等）」を「新規作成の導線は左レールにある」に修正 |

## 3. 変更前後の文言（UI に貼る）

### G1 — TC-UI-STATE-01（`tc_mw8elt1v_c58be897`）手順 1

- 変更前: `1. 各画面に空メッセージと次の導線（新規作成・再読込等）が出る`
- 変更後: `1. 各画面に空メッセージが出る（新規作成の導線は左レールのメニューにあり、空表示の中には無い）`

### G3 — TC-UI-STATE-01 手順 3

### G4 — TC-AUTHZ-01（`tc_mw8ee1k9_a00adcbe`）手順 3

- 変更前: `3. 403（承認できるのは承認者だけ）`

### G4 の残り（手順 1・4・6）— 再実行してから改訂

手順 3 以外の遷移拒否も 409 が返る想定だが、**未実測**のため先に再実行して確認する。確認できた手順だけ「403」→「409 / ERR-201」に置き換える。
