## 12. Ralph Loop の利用可否と制約（実環境）

- 本セッションでは `ralph` ツールが**利用可能**（不変の objective と `maxRounds` を渡す foreground 実行）。
- 制約（ツール仕様として確認した範囲）: 各 Round は**新しい子エージェント**で、親の会話・前 Round の会話を引き継がない（共有ワークスペースだけが長期記憶）。**人間への承認要求（数字選択）は行えない**。子は共有ワークスペースへ書き込むため、Agent Team と同時に走らせると書込みが競合しうる。
- したがって今回は **Ralph を起動していない**。理由: (a) 本バッチの中核判断が人間承認（§10-1）であり、承認を取れないループは要件を満たせない、(b) Agent Team が同一ワークスペースで稼働中で、`ralph` の子と書込み範囲を分離できない。
- 代わりに、要件の「調査 → 計画 → 実装 → 統合 → Build/Test → Review → 再評価」を **Lead の Round として同手順で実施**した（§2）。第 2 バッチで承認が得られ、書込みを 1 本に絞れる区間があれば、`ralph` を限定 objective（例: 証跡の独立再照合）で試す。
