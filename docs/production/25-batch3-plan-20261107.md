## 2. 各項目の受入条件

### B3-01 C-07: 有効利用者 0 件の検知

- `GET /healthz` の `auth` に `usersActive`（**有効な `app_user` の件数だけ**）を追加する。メール・ID・名前は返さない。
- `scripts/ops/healthcheck.mjs` が `auth.usersActive === 0` で非 0 終了する（prod healthcheck unit の ExecStart は `.mjs`）。
- DB 不達時は `usersActive` を返さず、既存の `status` / `db` の挙動を変えない（後方互換）。
- 受入: unit（0 件 / 1 件以上 / DB 不達）、integration（`/healthz` の形）、`bash scripts/ops/tests/healthcheck-*.test.sh` が緑。
- 記録: `docs/limitations.md` C-07 を「解消」に更新（残る限界があるなら残す）。
- **リスク**: 参照は `select count(*) from app_user where is_active` のみ。個人情報を出さない。

### B3-02 W-10: 色コントラスト 3 件

- 対象（`docs/test.md` §一覧の 1〜3）: `.offline` 3.04:1 / `.tm > .kd` 2.87:1 / `.big > small` 3.32:1。
- 最小改変で 4.5:1 以上にする（配色は原本側のため、上書き CSS を 1 箇所に集約する）。
- 受入: `tests/browser/a11y.spec.ts` の allowlist から該当 3 件を削除し、`pnpm test:browser:approver` が緑。
- 記録: `docs/test.md` の既知除外表を 9 件 → 6 件に更新。

### B3-03 L-03（第 1 段）: 添付の実保存

- 依頼（`request`）に対する添付のアップロード/ダウンロード。保存先は環境変数（既定 off）。
- 制限: 1 ファイル 10 MiB・合計 5 件・許可拡張子（pdf/png/jpg）・ファイル名は保存時に UUID 化（traversal 防止）・SHA-256 を記録。
- 受入: unit（上限・拡張子・traversal・SHA-256）、integration（認可・404・削除）、migration の up/down。
- **範囲外**: ウイルス検査・原本の加工・クラウド保存。`docs/limitations.md` L-03 を「第 1 段のみ」に更新。

## 6. 進め方

- 実装は worktree を分離し、main チェックアウトは main/clean を保つ（autofollow の前提）。
- 各 PR は **pr-ready で exit 0 → CI 3/3 → 独立レビュー（Critical/High 0）→ squash マージ**。
- 1 項目 1 PR を原則とする。文書のみの項目（B3-07 / B3-09 / B3-06）は 1 PR にまとめてよい。
- 失敗・未実施・skip を完了と書かない。証跡は実測値・run ID・SHA で示す。
