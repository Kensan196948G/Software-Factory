## 2. 設計

### 2-1. 画面構成

- 左: 判断を待つ依頼の一覧（`wait` 承認待ち → `review` 内容確認中 → `received` 受付 → `back` 差戻し の順。同じ状態内は滞留日数の降順）。
- 右: 右端固定パネル。見出し（状態・信号・滞留日数・受付番号・件名・部署・起票者・更新・月あたり時間）、要点（困りごと・目的は2行まで、作るもの/作らないは各3件まで、合格の条件は4件まで、残りは「ほか N 件」）、受付チェックの札、操作ボタン。
- パネルはスクロールしない。高さが足りない画面（`max-height: 760px`）では「作るもの/作らない」を省く。
- 幅は画面の約40%（420〜620px）。1080px 以下では一覧の下に積む。

### 2-2. 操作と既存資産の再利用

- 「進める」は既存の `advance()`、「承認する」「差し戻す」「状態を変更」は既存の状態変更ダイアログ（`openStatus()`）を呼ぶ。
- 承認は既存の**承認前チェック（自動）**・信号の色の決定・メモをそのまま通る。サーバ保存・監査（`audit_log`）・版管理・409/ERR-201 の遷移規則は変更しない。
- ボタンは役割で出し分ける（`canMoveR`）。「次に動かすのは誰か」を基本に表示し、「いまの役割では進められません」は**押せる操作が1つもない場合だけ**出す（承認者は自分の番でなくても状態を動かせるため、メッセージとボタンが食い違わないようにする）。
- 「全文を開く」は既存のドロワーを開く（全文・注文書・コメント/履歴）。

### 2-3. 追加した識別子

- 画面: `data-v="review"`、`#rlist`、`#rpanel`、行 `.rrow[data-id][data-status]`。
- 操作: `#rvNext` / `#rvApprove` / `#rvBack` / `#rvStatus` / `#rvOpen`。
- ナビのバッジ: `#bdgReview`（判断を待つ件数）。
