## 1. 位置づけ

- 出典: ADR `00-adr.md` §8.2 の Q4。所有者が選んだ選択肢 1 は、運用保証を 10 ステップで設計・実証するもので、その文言「**設定変更が必要なものは都度 Y/N で確認します**」に従い、下表の「設定変更あり」の行は実施前に所有者の Y/N を 1 件ずつ取る。
- ここでいう「運用保証」は**可用性の保証ではない**。バックアップ・通知・復旧・資格情報・保持・統制について、**保証活動（設計・訓練・確認）と証跡（記録・PR・実測）を揃える計画**である。月間可用性・RPO/RTO の目標達成を約束するものではない（目標値の確定は Q-12、所有者確認待ち）。
- 「設定変更」は、本番・Staging の systemd unit・設定ファイル・資格情報・Cloudflare（Access/DNS/Tunnel/R2）・GitHub のリポジトリ設定・DB の変更を指す。docs・コード・スクリプトの PR は含まない（main への反映は通常の PR 手順）。

## 4. 記録のルール

- 状態を更新するときは、日時・PR 番号または commit・実測値の出典（ログのパスや記録文書）を書く。値（秘密・個人情報）は書かない。
- 「完了」は成功条件を満たした証跡がある場合だけ。未実施・失敗・skip を完了と書かない（AGENTS.md §5）。
- Y/N を取った場合は、質問・回答・日時を該当行または `00-adr.md` に記録する。
