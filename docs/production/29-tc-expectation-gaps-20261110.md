## 5. G4 の判定（2026-11-10）

**判定: 実装（409 / ERR-201）が正しく、TC の期待値（403）が過剰指定。コードは変更しない。TC を UI で改訂する。**

根拠:

- `docs/api.md:68`: 「拒否時は 409 `ERR-201`（理由と「できる人」を含む）。不正な遷移も監査ログに残す。」— 遷移の拒否は 409 と明記されている。
- `docs/project/01-mvp-scope.md:78`: 「不正な遷移・権限外の操作が **403/409** で拒否され、監査ログに残る」— どちらも要件上許容。
- 実装: `src/api/service.ts` の `performTransition` は、`roleCanTransition` が不許可のとき `Errors.invalidTransition(...)`（409 / ERR-201・理由つき）を返し、監査に `request.transition_denied`（reason=not_allowed, why）を残す。
- 403 は「管理 API の権限不足」と「自己承認（ERR-105）」で使われており、遷移の拒否は 409 に統一されている。

TC 改訂案（UI で編集。実測済みの手順 3 を先行）:

- 手順 3 の期待: 「403（承認できるのは承認者だけ）」→「**409 ERR-201**（承認できるのは承認者だけ。理由が返り、状態は変わらない）」
- 手順 1・4・6 は遷移拒否のため同じく 409 が返る想定だが、**再実行して確認してから**改訂する（未実測のまま期待値を変えない）。

改訂後、TC-AUTHZ-01 は executed のまま（挙動は変わらず、期待値のみ実測に合わせる）。
