### 開発ラインの AI の工具

- AI の工具は Read と Edit だけ。コンテナ内で試験もコマンドも実行できず、試験の実行と合否は独立した CI が行う。
- ファイルの一覧と検索の工具が無いので、注文書とプロンプトにある path しか確実に読めない。注文書の `scope` に対象のファイルを書く。
- AI が書いた試験の誤りは、修正の上限か `human_approval_required` で止まることがある（`docs/devline/real-runner.md` 9-2 章）。

### 開発ライン最終段（人の承認 → merge → 検証環境への配備 → 戻し）

- 本番公開の経路は作っていない（SC-02、SC-03 が未決）。job は `staged` で止まり、`released` と `closed` は使わない。
- 実走は Staging で作り物 2 件（`docs/devline/real-runner.md` 16 章）。失敗の経路（配備の失敗からの自動の戻し、`artifact_mismatch`、結果不明の merge の照合）は fake GitHub、stub の docker、部品試験でのみ確認。
- 成果物の取得は遅い（実測 約 140 kB/s、79 MB で 8〜9 分）。遅い原因は未調査。取得の間は worker の他の処理が止まる（上限 30 分）。
- 配備先はこのホストのローカル Docker の内部ネットワーク（公開ポートなし。このホストからコンテナの IP で届く。外部へ出られない）。古いイメージを自動で消さない（戻し先に使うため）。
- 戻せるのは1つ前の digest まで。前の版のイメージが消えていれば `image_missing` で失敗する。
- 配備の途中で内部エラーになると環境の版を不明として記録し、次の配備は戻し先なしで進む。
- merge 後に tree を確認できなかった依頼で押し直すと、tree を読み直すが、一致でも不一致でも押し直した人の監査が残らない。取得へ進めば、その結果だけ worker が `job.build_result` に記録する。
- 反映した画面が届くのは、HTML がブラウザにキャッシュされないことが前提。今は HTML に `Cache-Control` がなく、Cloudflare は `DYNAMIC` で返す（2026-11-02 に確認）。Cloudflare の設定を変えると前提が崩れる。
- merge の結果不明は人の押し直しでだけ照合する。worker は GitHub の PR を読まない。
- PR の head が変わるなどで失効すると、その job は `pr_ready` のまま merge できない。注文書の版を上げて作り直す。
- 役割の切替は MVP の作りで、次の差が残る。運用、セキュリティ、管理、監査の画面の役割はサーバでは承認者として動き、再読み込みすると承認者の表示に戻る。切替の保存に失敗すると、通知は出るが画面の役割は戻らない。別のタブは次に読み込むまで古い役割を表示する。切替の直後に再読み込みすると前の役割に戻ることがある。
- 1ユーザーで3役を切り替える MVP では、merge の承認者と依頼者の分離は技術的に保証されない（L-01、L-02）。**職務分離を満たさず、本番の承認統制を満たさない**（画面にも明記）。`app_user.is_agent` の登録も人の運用。
- 承認は `POST /api/jobs/:id/revoke-approval` で取り消せる。GitHub へ送信中は取り消せない。結果不明の merge は取り消しても事実が変わらないので、照合で確かめる。
- 「digest」は CI の `docker save` と同じイメージ ID（`sha256:...`）。レジストリの digest ではない。配備するのは CI で検査したイメージそのもので、このホストで作り直さない。合否の根拠にした run に artifact `image` が無ければ止まる（Sandbox PR #5 より古い run を含む）。
- イメージ ID の一致は、CI と host の Docker のイメージストアが同じ形（overlay2 など）であることを前提にする。違えば `artifact_mismatch` で止まる（実 GitHub の artifact 2 件は一致）。
- artifact の保存期間は 14 日（Sandbox の ci.yml）。過ぎた run は `artifact_expired` で止まる。

## 3. 環境・運用の制限

- ローカルホストが停止するとPreviewも停止する。
- PostgreSQLはローカルのみ。クラウドDBへの移行はBacklog。
- CIは `.github/workflows/` のポリシーゲートにより未適用（[patches](patches/README.md)）。ローカル検証で代替。
- 数値目標（応答時間・可用性・RTO/RPO）は（案）。MVP実測後に確定（Q-12）。
