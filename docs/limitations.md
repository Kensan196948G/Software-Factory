# 既知の制限・残存リスク（MVP）

最終更新: 2026-10-28

## 1. 機能の制限

| # | 制限 | 影響 | 本番までの対応 | 管理 |
|---|---|---|---|---|
| L-01 | 1ユーザー・パスワード認証。3役は画面で切替 | 職務分離が技術的に保証されない | Entra ID SSO＋複数ユーザー＋承認者マスタ | Backlog / Q-13 |
| L-02 | 自己承認を許可（`ALLOW_SELF_APPROVAL=1`） | 本番の統制（ERR-105）を満たさない | 本番は `false`＋SSO | Backlog |
| L-03 | 添付はファイル名・サイズのみ | 実体の保存・ウイルス検査・ハッシュがない | 文書管理へ保存（Q-17） | Backlog |
| L-04 | 通知（NEO／メール／GitHub）なし | 承認依頼・滞留の通知が届かない | IF-02/FR-44 | Backlog / Q-01 |
| L-05 | 開発ライン連携は注文書YAMLの生成・コピーまで | Issue自動作成・AI実装・CI連携はない | FR-28〜46 | Backlog |
| L-06 | AppSuite版UI・A4印刷なし | 受付はオリジナル画面に一本化 | Q-01 | Backlog |
| L-07 | 現場試用の「感想を書く」はコメント追加で代替 | 専用の試用記録フォームはない | 州のヒアリングで設計 | Backlog |
| L-08 | 一覧の信号絞り込みはサーバ取得後にJSで実施 | 数千件規模ではメモリを使う | SQLで候補色を計算 or マテリアライズ | 性能 |
| L-09 | 添付・印刷・多言語の一部は未実装 | 仕様の一部 | 各Issue | Backlog |

## 2. セキュリティの残存リスク

| # | リスク | 対策 | 残るリスク |
|---|---|---|---|
| S-01 | 個人MVPの自己承認 | 設定で無効化可能・監査に記録 | 1ユーザーでは無効化するとフローが止まる |
| S-02 | パスワードを会話・ローカル設定で共有 | scryptでハッシュ保存・ローテーション可能 | 初期パスワードの共有経路 |
| S-03 | Cloudflare Access 未設定時はアプリ認証のみ | 強固なパスワード＋レート制限＋CSRF | 公開URLへの総当たり（レート制限で緩和） |
| S-04 | origin共有秘密が漏れるとWorker迂回 | Tunnelは公開せず、ホスト名を秘匿 | Cloudflare側の設定漏えい |
| S-05 | 監査ログの改ざん | 追記トリガ＋ハッシュ連鎖 | DB管理者権限では可能 |
| S-06 | 依存関係の脆弱性 | Dependabot/監査は未設定 | 本番前に `pnpm audit` と更新 |

## 3. 環境・運用の制限

- ローカルホストが停止するとPreviewも停止する。
- PostgreSQLはローカルのみ。クラウドDBへの移行はBacklog。
- CIは `.github/workflows/` のポリシーゲートにより未適用（[patches](patches/README.md)）。ローカル検証で代替。
- 数値目標（応答時間・可用性・RTO/RPO）は（案）。MVP実測後に確定（Q-12）。
